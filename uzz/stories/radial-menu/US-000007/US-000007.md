## radial-menu/US-000007 — Render Menu Item Labels in Wedges

### User Story

```
AS A user
I WANT each radial menu wedge to display its item label
SO THAT I can identify every action at a glance without an external legend
```

#### Status
TODO

#### Dependencies
- None

#### Technical Context & Constraints
* **Target System**: JavaFX desktop applications embedding the radial-menu component
* **Toolchain / Rules**: Java 25 + JavaFX + Maven; JUnit 5, AssertJ, and headless JavaFX tests; AtlantaFX 2.1.0
* **Phase**: N/A

#### Notes
1. Labels are additive. Selection semantics, hover feedback, the selection callback, public constructors, and hub rendering must remain unchanged.
2. Render each non-empty `MenuItem.label()` at the wedge mid-angle, upright, and centred on the label anchor.
3. Expose `labelRadiusRatio` (`0` = inner radius, `1` = outer radius, default `0.5`) as a `DoubleProperty` and as the styleable property `-rm-label-radius-ratio`, following standard JavaFX CSS precedence.
4. Add the `radial-menu-label` style class to every label text node. Support `-rm-label-fill` (looked-up colour defaulting to the AtlantaFX text colour) and `-rm-label-font-size` (styleable size defaulting to diameter × 0.05).
5. Use a per-wedge usable box derived from the chord at the label radius, the radial band thickness, and a safety margin. Single-line labels only.
6. When text does not fit, reduce the font size no lower than 70% of the default, then truncate with an ellipsis. When CSS explicitly sets `-rm-label-font-size`, do not shrink; truncate only.
7. When `MenuItem.icon()` is present and the icon plus label fit together, render the icon above the label. Otherwise render the icon alone. Scale icons uniformly within their allotted area.
8. Make the label layer and its descendants mouse-transparent so clicks and hovers fall through to the wedge.
9. Rebuild labels when the observable `items()` list changes and reposition them during layout and geometry rebuilds.
10. Wedge labels currently use the fixed 60/135 radii. Diameter-driven re-layout is deferred to FR-2 (bindable overall diameter), which is out of scope for this story.
11. Extend the demo with labelled items and, where practical, an item with an icon. Update `README.md` with the new API and CSS hooks.

### Acceptance Criteria

```gherkin
Scenario: Labels appear in every wedge
  Given a radial menu with items labelled Scope, Story, Code, and Explore
  Then each wedge displays its label
  And every label node has the style class radial-menu-label
  And the labels are upright and centred in their wedges

Scenario: Labels sit at the default band midpoint
  Given a radial menu with default label settings
  Then each label anchor is at the midpoint between the inner and outer radii
  And each anchor lies on its wedge's mid-angle

Scenario: Label distance is configurable through the API
  Given a radial menu with labelRadiusRatio set to 0.75
  Then each label anchor lies at 75% of the radial band
  And changing the ratio repositions the labels without rebuilding the items

Scenario: Label distance is styleable
  Given an author stylesheet declaring -rm-label-radius-ratio: 0.75 on .radial-menu
  Then the labels use 75% of the radial band
  And a bound labelRadiusRatio remains authoritative

Scenario: Labels do not block interaction
  Given a radial menu with labelled wedges
  When the user clicks a label
  Then the corresponding selection callback is invoked
  And the wedge enters its selected state

Scenario: Labels pass hover through to the wedge
  Given a radial menu with labelled wedges
  When the pointer moves over a label
  Then the underlying wedge receives the hover state

Scenario: Long labels stay inside their wedges
  Given a radial menu with a label wider than the chord at its label radius
  Then the label font is reduced no lower than 70% of the default
  And the label is truncated with an ellipsis when it still does not fit
  And no label box crosses into a neighbouring wedge

Scenario: Explicit CSS font size disables auto-shrink
  Given an author stylesheet declaring -rm-label-font-size: 18px
  And a label that cannot fit its wedge at that size
  Then the label is truncated with an ellipsis
  And its font size remains 18px

Scenario: Styling hooks apply
  Given an author stylesheet declaring -rm-label-fill: red
  Then every label uses red text
  And without overrides labels use the AtlantaFX default text colour

Scenario: Icon and label stack when they fit
  Given an item with an icon and a short label
  Then the icon is rendered above the label
  And both stay inside the wedge's usable label box

Scenario: Icon-only fallback
  Given an item whose icon and label cannot fit together at the minimum font size
  Then the icon is rendered without the label
  And the icon remains inside the wedge

Scenario: Items changes rebuild labels
  Given a radial menu with two labelled items
  When an item is added or removed through items()
  Then the label layer matches the new item list
  And removed items leave no stale label

Scenario: Layout repositions labels
  Given a radial menu whose geometry has been rebuilt
  When the control performs layout
  Then every label is re-centred on its wedge's mid-angle

Scenario: Empty menu
  Given a radial menu with no items
  Then no segments and no labels are rendered

Scenario: Invalid ratio is clamped
  Given labelRadiusRatio is set below 0 or above 1
  Then the effective value is clamped to the nearest valid bound
```
